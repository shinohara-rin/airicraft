# Codex Driver Survival Playthrough

Date: 2026-09-01  
Mode: external Codex driver (`scripts/codex-driver`)  
Objective: progress from a fresh survival world to the Ender Dragon, using only the exposed Airicraft agent tools for gameplay.

## Rules of this log

- Record non-fatal bugs with the evidence, workaround, and gameplay impact.
- Record missing but non-mission-critical harness capabilities separately.
- Do not treat a queued tool result as completed work; wait for its task state and events.
- A true blocker is a failure that prevents progress with every available exposed tool and has no safe in-game workaround.

Client `worldTime` is not used as server-simulation proof because the client continues rendering/ticking for snapshot capture.

- `91f66673` prevents recipe automation from reusing a workstation substantially below the player when a portable crafting table is carried. The automated regression is green; the original terrain has not been replayed live.
- `db2da62d` accepts overworld planks as surface-tower filler and terminates 100 consecutive `support_unavailable` ticks instead of livelocking. Broader shore discovery remains open.
- `48055ad9` makes every `AWAITING_PLANNER` survival hold resumable by requiring and, for a safety-only drowning hold, generating a `holdId`. The status/action time-of-check race remains possible and should still be handled as a normal rejected action.

## Non-fatal bugs / workarounds

- **Tick-debug snapshot world-time mismatch.** Evidence: pause snapshot at `clientTickId=914` reported `worldTime=318`; the one-step snapshot at `clientTickId=915` reported `worldTime=640`. Workaround: use `clientTickId`, `pauseEpoch`, and snapshot IDs as the timing authority, not `worldTime`, until clarified. Impact: no current gameplay block, but it weakens time-sensitive debugging evidence.
- **Navigation can fail at the destination perimeter.** Evidence: `navigate_to(284,67,-141)` started at `(65,67,-86)`, moved the player to `(281,65,-144)`, then ended `CALCULATION_FAILED` / `Path calculation failed` with an estimated 25 ticks remaining. The target was visibly in a small azalea/oak forest. Workaround: once within local-resource range, switch to the typed resource collector rather than retrying the same exact navigation goal. Impact: non-fatal for local collection, but unreliable for objectives requiring a precise target block.
- **Exact break drop collection remains weak but recoverable; tool and reached-goal reporting are fixed in source.** `break_blocks` can return `pending_timeout` after lower blocks are broken, and drops are not proactively chased beyond pickup radius. `4c9c49ea` now selects the best valid inventory tool before every exact break. `a18d2b7b` maps `CALC_FAILED` to goal reached only when the active exact navigation goal is in fact satisfied. Workaround for the remaining issue: navigate to each known drop coordinate.
- **Automatic workstation selection cave preference is fixed in source; live terrain replay is pending.** In the original run, a carried crafting table was ignored in favor of a table around five blocks below the player, routing a safe surface player into a natural cave. `91f66673` makes a substantially lower found table ineligible when a portable table is carried, and its policy regression passed. Explicit surface placement remains the conservative workaround until that exact terrain is replayed live.
- **Tick-debug pause did not freeze hostile damage (fixed live 2026-09-04).** Historical evidence: after `pause` returned `paused: true`, `clientTickId=3963`, and `pauseEpoch=1`, the event stream recorded an arrow hit, fall damage, four zombie hits, death, and respawn, all at tick `3963`. The client-only tick gate let the integrated server continue running. Fix: `fd7d7743` makes the server own pause/step state and gates `MinecraftServer.tick`; the client now only coordinates frame capture. Live verification held `serverTickId=127` for 10 seconds paused and allowed exactly one tick (`128`) for one `step`. This freezes server-side mob AI, damage, and world simulation while preserving client-side snapshot rendering.
- **Blocked collection retained an active mine primitive (fixed live).** Evidence: wood collection declared `WAITING_FOR_PICKUP` / `target_missing` after collecting 4 of 16 logs, but its active mining task continued, moving from Y=67 to Y=44 before a hostile reflex. Cause: a blocked collection job still exposed its mine goal and retained its desired primitive request. Fix: only `RUNNING` collection jobs may expose or retain a primitive. Focused `EmbodiedAgentRuntimeTest` passed; hot-reload validation submitted a no-target one-log goal and confirmed `taskExecution=IDLE`, no goal ownership, and no movement.
- **Task lifecycle responses amplified full world evidence (fixed live).** Evidence: plain `agent tasks resume` and `agent tasks cancel` each emitted about 306k tokens, including the full known craft/smelt catalog, for a one-line lifecycle acknowledgement. Fix: the normal wrapper view now projects only lifecycle, compact reflex, compact task execution, and compact task fields; `missionExecution` remains verbose-only. `AiricraftCliMainTest` covers the omission, `:wrapper:test` passed, and the rebuilt CLI returned the bounded cancellation response against the live client. Commit: `b18376a`.
- **Survival reflex status/action race remains; the unresumable drowning wedge is fixed in source.** Evidence: `agent status` reported `reflex.state=IDLE`, then an immediate `craft_recipe` was rejected as `reflex_active`. Later it stayed `AWAITING_PLANNER` for `DROWNING` with full air and no `holdId`. `48055ad9` now requires a hold identity for `AWAITING_PLANNER` and generates one for safety-only drowning holds; focused runtime tests cover resume from that state. Workaround for the remaining race: treat `reflex_active` as authoritative and retry only after the new reflex epoch resolves. Live drowning was not deliberately induced during the remediation pass.
- **Placement-site query and executor used different stance policies (fixed live 2026-09-05).** The original water theory was wrong: vanilla placement legitimately replaced water with a crafting table. The defect was that `find_placement_sites` used a simpler horizontal-adjacency check while the executor additionally required its candidate set, interaction range, and line of sight. Fix: `inspect_world(find_placement_sites)` now delegates stance selection to the executor and reports `placementStand`. Live verification returned target `(18,19,-14)` with `placementStand=(18,17,-12)`, then `place_block` completed there, changing `minecraft:water` to `minecraft:crafting_table`.
- **Terminal navigation could retain a stale mutation gate (fixed live).** Evidence: after a `navigate_to` terminal `CALC_FAILED` and explicit cancellation, `agent status` showed no runnable job but `craft_recipe` was denied `active_task_in_progress` because its old `PAUSED_BY_REFLEX` execution snapshot was consulted before the terminal task/job states. Fix: terminal semantic task + terminal/idle active job now wins over stale execution state. Focused `EmbodiedAgentRuntimeTest` passed. After a client restart, the live pickaxe call reached its true `crafting_table_place_failed ... site_not_found` result rather than the stale-task denial. Commit: `7e4a1c5`.
- **`return_to_surface` no-support livelock is fixed in source.** Evidence: the original executor stayed `RUNNING` for more than 1,400 ticks at `towering:support_unavailable`, and its defaults ignored available oak planks. `db2da62d` adds overworld planks to the default filler set and fails deterministically after 100 consecutive unsupported ticks. Focused executor/argument tests passed, and the restarted live tool schema exposed the expanded defaults. This bounds failure; it does not discover distant shore.
- **Nearest surface search is too local after reflex displacement.** The search radius was widened from 12 to 16 blocks (`f53b49e`) after it missed proven village terrain about 15 blocks away; focused `SurfaceMemoryTest` passed. The fix helps at that boundary, but a later reflex moved the player to `(-104,60,-44)`, where no forest was found in the loaded 256-block feature search and the camera showed only open ocean floor. A local surface-memory scan still cannot recover from this class of displacement.
- **Mob flee used blind movement and could enter water (fixed).** The reflex now selects loaded, dry, hazard-free standing targets that increase separation, prefers cover, reaches targets through short exact Baritone hops, and raises the configured water traversal cost while it owns the route. If water is already moving or submerging the player, it hands recovery to the existing water-aware safe-standing navigator before resuming ground flee. The deterministic water regression remains useful for exact terrain control, but live acceptance now runs in the untouched, naturally generated snowy-forest `pickup` world.
- **A short flee could falsely resolve and wait for the pursuer (fixed).** Threats are retained while alive and loaded rather than dropped at 12 blocks. Security uses each mob's own route toward the player, not L2 distance or player-origin reachability: a zombie below a three-block pillar and a skeleton behind a sealed wall can be inaccessible even when close, while ranged line of sight remains dangerous. Complete routes of at least 16 nodes require 60 stable ticks; null/partial routes require 200 ticks, so a transient partial path is not accepted as shelter. The first natural run exposed the old short confirmation by resolving at tick `1087` before the same zombie returned at `1192`; that criterion was removed.
- **Close single-mob combat now terminates the encounter (fixed live).** In the final natural-world run, a low-health reflex started `FLEE` at tick `478` and immediately emitted `reflex.flee_knockback` against the zombie at `2.05` blocks, before path selection. It switched to `DEFEND` when safe, continued cooldown-timed `reflex.close_quarter_attack` hits, earned `Monster Hunter` at tick `564`, and resolved `threats_clear` at tick `565` without a second safety epoch. The exact tick-`1577` post-combat snapshot was survival mode at `(16.57,80.0,5.38)`, alive with full health, on dry ground, and not touching or submerged in water.
- **High-level diamond mapping and bootstrap selection are fixed live.** The original route chose `diamond_block_to_diamond`. After `70639dbc` and `4890f796`, a restarted client resolved the same fresh-inventory `DIAMOND` goal to wood collection, crafted sticks and pickaxes, raw-iron mining/smelting, and a final `minecraft:diamond_ore` mining step. The 30-step live route contained no leaf mining, `minecraft:iron_block`, or `minecraft:diamond_block`; it was cancelled after route proof rather than left to mine unattended.

## Harness gaps / discoveries (non-mission-critical)

- **Exact block break exists but was easy to miss in discovery.** `break_blocks` is an exposed, coordinate-grounded tool; it requires a fresh `inspect_world`/feature read and direct interaction range. At `(8,70,-104)`, inspection found five oak logs at `(8,69..65,-104)` and `break_blocks` completed the top four. `inspect_inventory` then confirmed `minecraft:oak_log=5`. This is the safe workaround for the earlier `mine_blocks` divergence, not a missing API.
- **Automatic workbench setup needs a feasible-site explanation.** `craft_recipe` correctly reported `crafting_table_place_failed`, but the driver needs the exact rejected terrain constraints and a preferred reachable target, not just `site_not_found`, to recover without trial-and-error.
- **Surface recovery now has a bounded water-aware route, not global shore discovery.** Mob flee and drowning recovery can reach a loaded safe-standing target without blind swimming, but `return_to_surface` still depends on remembered or locally discoverable land. A player already displaced into an open ocean beyond that bounded search still needs persistent safe-ground memory or broader shore discovery.

## Genuine blockers

- **Deep-cave mining still lacks a complete survival-readiness gate (observed live 2026-09-01; illumination and resource routing fixed live).** On the fresh forest-world run, explicit diamond mining descended from the established Y=48 mine into an unlit cave at Y=-6 without food, armor, a bed, or a safe-return plan. A skeleton-driven reflex then preempted resupply; releasing it resulted in death and eventual inventory despawn. `d456010` now rejects predicted underground mining with zero torches unless `allowUnilluminated=true`, and the remediated high-level route now targets ore rather than a diamond block. A full readiness gate still needs food, armor/weapon, and bounded exit/bed ownership before deep mining can be called survival-safe.
- **Entity discovery is too local for bed-first survival.** `inspect_nearby_entities` is a 32-block scan. Several controlled forest sweeps found no sheep, but there is no typed entity-search/exploration primitive to pursue wool before night. A bed-first policy needs an entity acquisition route that can search safely and return to shelter, rather than falling through to cave mining.
- **Ranged-mob reflex remains fatal even after the lighting fix (second live reproduction).** A fresh daylight restart safely progressed to stone pickaxe, surface coal, four torches, three raw iron, a surface furnace, and three smelted iron ingots. At night, a creeper at 5.4 blocks and skeleton at 11.3 blocked crafting. The reflex moved uphill, but its main hand became `leaf_litter` despite a stone pickaxe in the hotbar. Two controlled five-second release windows reduced health from 20 to 17.17 and then 13.53 while the skeleton remained around 11–12 blocks away. The client is paused at that point. Tick pause is diagnostic only and cannot be used as combat protection because the integrated server continues to deliver damage. A viable reflex needs a ranged-threat exit rule that reaches actual cover/line-of-sight break promptly, preserves/equips an available combat tool, and must not leave the player in an unbounded active-reflex state.

- **The displaced saved state still lacks distant-shore and worktable recovery.** The player can be driven from the original water column to the village coast, but the drowning reflex subsequently displaced it back into water. Automatic crafting-table setup finds no site there, direct placement finds no adjacent support, and the bounded surface return has no distant-shore target. The new flee policy prevents fresh blind-water routes and the no-support executor now terminates instead of livelocking, but neither change invents a distant shoreline target. Resume from a known dry checkpoint or add broader shore discovery plus water-aware placement ownership before treating this save as unblocked.
